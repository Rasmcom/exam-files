# سحابة أعمال الاختبارات

منصة ويب عربية مستقلة وآمنة لحفظ أعمال الاختبارات وتنظيمها حسب **العام الدراسي ← الفصل الدراسي ← التبويب ← المجلد**. المشروع مخصص لحساب واحد فقط، ولا يتضمن تسجيلًا عامًا أو مستخدمين إضافيين.

## ما يتضمنه المشروع

- صفحة دخول خاصة بهيرو متحرك عن أعمال الاختبارات.
- لوحة تحكم عربية RTL متجاوبة مع الكمبيوتر والجوال.
- إنشاء أعوام دراسية؛ ويُنشأ الفصلان الدراسيان تلقائيًا.
- تبويبات افتراضية لأعمال الاختبارات، مع إمكانية إنشاء تبويبات ومجلدات إضافية.
- رفع عدة ملفات بالسحب والإفلات.
- دعم PDF وWord وExcel وPowerPoint والصور وTXT وCSV وZIP.
- حد أقصى 50 ميجابايت للملف الواحد.
- عرض شبكي وجدولي، وبحث، ومفضلة، وأرشيف، وسلة محذوفات واستعادة.
- تنزيل آمن عبر رابط موقّع مؤقت لمدة 60 ثانية.
- سجل عمليات للرفع والتنزيل والحذف والاستعادة والمفضلة.
- قاعدة بيانات PostgreSQL وحاوية ملفات خاصة عبر Supabase.
- سياسات Row Level Security تحصر البيانات والملفات في حساب المالك المسجل فقط، مع قيد قاعدة بيانات يمنع تسجيل مالك ثانٍ.
- وضع معاينة محلي لتجربة الواجهة دون اتصال بقاعدة البيانات.

## تشغيل المعاينة محليًا

أنشئ ملف `.env.local`:

```env
VITE_DEMO_MODE=true
VITE_OWNER_EMAIL=owner@example.com
```

ثم:

```bash
npm install
npm run dev
```

المعاينة لا ترفع ملفات فعلية، لكنها تعرض جميع أجزاء الواجهة وحركاتها.

## ربط Supabase

### 1. إنشاء المشروع

أنشئ مشروع Supabase جديدًا مستقلًا، ثم شغّل الملف التالي كاملًا داخل SQL Editor:

```text
supabase/migrations/202608220001_initial_schema.sql
```

ينشئ الملف:

- الجداول والفهارس.
- سياسات RLS.
- الحاوية الخاصة `exam-files`.
- سياسات التخزين.
- الدالة التي تنشئ العام والفصلين والتبويبات الافتراضية.
- سجل العمليات.

### 2. إنشاء الحساب الوحيد

انسخ:

```text
.env.owner.example
```

إلى:

```text
.env.owner
```

ثم أدخل رابط المشروع ومفتاح `service_role` والبريد وكلمة المرور الطويلة، وشغّل:

```bash
npm run create-owner
```

السكربت ينشئ المستخدم أو يحدّثه، ثم يسجله بصفته المالك الوحيد في جدول `portal_owners`.

> مهم: ملف `.env.owner` ومفتاح `service_role` لا يُرفعان إلى GitHub ولا يوضعان في متغيرات الواجهة.

### 3. تعطيل التسجيل العام

من إعدادات Supabase Authentication عطّل إنشاء حسابات جديدة. لا توجد صفحة تسجيل داخل المشروع أصلًا، كما أن سياسات قاعدة البيانات تمنع أي مستخدم غير مسجل في `portal_owners` حتى لو أُنشئ بطريق الخطأ.

### 4. متغيرات الواجهة

انسخ `.env.example` إلى `.env.local` وأكمل القيم؛ ويجب أن يطابق `VITE_OWNER_EMAIL` البريد الذي أنشأه سكربت المالك:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
VITE_STORAGE_BUCKET=exam-files
VITE_OWNER_EMAIL=owner@example.com
VITE_DEMO_MODE=false
```

### 5. البناء

```bash
npm install
npm run typecheck
npm run lint
npm run build
npm run preview
```

## النشر

المشروع SPA ويمكن نشره على Vercel أو Netlify أو Cloudflare Pages. إعداد البناء:

```text
Build command: npm run build
Output directory: dist
```

أضف متغيرات `VITE_*` في إعدادات منصة النشر، ولا تضف `SUPABASE_SERVICE_ROLE_KEY` مطلقًا.

## بنية الملفات

```text
src/
  components/       مكونات الواجهة والملفات والحوارات
  contexts/         جلسة الدخول والحساب الوحيد
  hooks/            عمليات قاعدة البيانات والتخزين
  lib/              الإعدادات والأدوات وعميل Supabase
  pages/            صفحة الدخول ولوحة التحكم
  types/            أنواع البيانات
supabase/
  migrations/       مخطط قاعدة البيانات وسياسات الأمان
scripts/
  create-owner.mjs  إنشاء الحساب الوحيد من بيئة خادم آمنة
docs/
  ARCHITECTURE.md    وصف البنية ونموذج العزل
SECURITY.md          تعليمات الأسرار وضوابط الرفع
```

## ملاحظات الأمان

- حاوية الملفات غير عامة.
- كل مسار تخزين يبدأ بمعرّف المستخدم.
- لا تُستخدم روابط تنزيل دائمة.
- الملفات التنفيذية والبرمجية غير مسموحة.
- لا توجد بيانات اعتماد افتراضية داخل المستودع.
- الحذف من الواجهة حذف مرن قابل للاستعادة، ولا يمس الملف مباشرة.
